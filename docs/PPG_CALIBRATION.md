# PPG 真实设备校准：第一轮诊断

## 证据与当前结论

用户反馈：真实手机 HTTPS、后置摄像头、torch、25 秒流程正常；能观察到信号变化，但反复拒绝，尚无稳定 accepted BPM。已知手机为一加 Ace2 Pro（PJA110），浏览器版本 `40.10.21.1_66b0631_260821`；OS 版本和原始 RGB 序列尚未取得。不能把流程正常视为心率测量通过，也不能从拒绝码诊断真实心率异常。

审查 latest main 2074fb4 后发现：

- 只有线性去趋势与三点平滑，不能充分消除非线性曝光漂移。合成 72 BPM + 20*exp(-t/5) 亮度漂移会被拒绝：前后段主频一致，但整段 coherence 约 0.239。这是算法机制复现，不是本机故障确诊。
- 旧跳变阈值 max(3, 6*整段残差标准差) 会随跳变自身升高。合成 30 灰度阶跃漏过运动判断后被报为 bpm_out_of_range。现在额外取 max(3, 12*相邻帧绝对变化中位数) 与旧阈值的较小值；只加强拒绝，不允许旧版运动拒绝的样本借此通过。
- inconsistent_pulse 包含两种情况：前后段频率差 >8 BPM，或者某段 coherence <0.4。原来单一提示无法区分。新增 rejection_detail、两段主频、coherence 和差值，阈值不变。
- 当前固定中心 50% ROI 缩至 32×32，只有 RGB 均值；不清楚本设备是否存在局部过曝或覆盖不均。本轮追加每帧 ROI 红通道空间标准差及裁剪像素占比（仅本地导出），不自动换 ROI 或通道挑选更容易通过的结果。

## 此轮修改

- 预热默认从 1.5 秒改为 3 秒，可选择 1.5/3/5 秒进行对照；随后仍采集完整 25 秒，超时随预热调整。更长预热未在该物理手机上验证，不保证有效。
- 获取浏览器实际报告的分辨率、帧率、曝光/白平衡/对焦模式（缺失表示未报告）。不强制锁曝光，因为设备支持与实际曝光范围尚不明确。
- PPG REST 结果新增 diagnostics，summary 的 last_ppg_result 同步保留；不改 WebSocket、State Engine、Controller、Visual Mapper 或来源/TTL 规则。
- 页面“导出本次校准 JSON”导出最近完整采样、采集设置、ROI 统计、估算结果/错误。失败也能导出；无图像、无后台自动存盘，刷新/新测/重置清空内存。旧读数不会因此重新注入。
- `python scripts/replay_ppg.py 文件.json` 离线重放，只有算法计算，不发 HTTP、不跳过主流程的 session/TTL 检查。诊断主频是候选频率，绝不是被接受的真实 BPM。

## 下一次手机复测

1. 提供手机型号、OS、浏览器版本、镜头位置及是否在中途调整手指。
2. 同一设备和姿势，先 3 秒预热，失败后立即导出；再用 5 秒复测并导出。保留失败样本，不只提供最好的一次。每次间隔休息，发热或不适立即停止。
3. 记录 failure_reason/rejection_detail；建议至少提供三次完整记录，分别覆盖已遇到的拒绝类型。JSON 包含会话标识和设备信息，分享前检查。
4. 有样本后离线比较：低频漂移去除、频带滤波、多个短窗谱峰一致性，以及谐波/真实低频异常的区分。所有改进均须同时跑噪声、运动、掉帧、低/高频拒绝样本；不能仅凭 accepted 比例选算法。
5. 如像素饱和或覆盖不均明显，再评估曝光能力和固定 ROI 对照；不同时改变预热、ROI、滤波和阈值，否则无法归因。

尚未上线新的高通/带通滤波或放宽 8 BPM / coherence / quality 阈值。原因是没有真实失败波形，盲目去掉低频能量可能掩盖运动，或把谐波当成心率。Apple Watch 仍仅 Adapter/文档；此轮无医学或跨设备准确性验证。
