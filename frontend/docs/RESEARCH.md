# 渐静：生理反馈可视化调研与实现

调研日期：2026-09-10。目标是将已有后端的连续交互参数，转成可以感知的状态变化，并提供呼吸引导。

## 项目比较

| 项目 | 已有交互 | 本项目借鉴 | 复用边界 |
|---|---|---|---|
| [Muse](https://choosemuse.com/pages/app) | 将传感器信号转成天气声景，并回顾 calm / neutral / active 状态 | 用连续环境变化反馈状态，避免只有一个分数 | 产品交互参考；不使用其算法、声景、品牌素材 |
| [DEEP](https://www.exploredeep.com/) | 呼吸控制 VR 世界中的移动，环境随呼吸变化 | 生理节律与视觉节律的联系；沉浸体验 | VR 研究与产品参考，未复用代码或场景；原型尚未验证其效果 |
| [Moonbird](https://play.google.com/store/apps/details?id=life.moonbird.aura) | 触觉呼吸节拍，应用提供心率和 HRV 等实时反馈 | 将引导目标与实测呼吸频率分别显示 | 商业产品参考；本后端尚无 HRV，故页面不显示虚构 HRV |
| [HeartMath Inner Balance](https://store.heartmath.com/) | 心律相干性测量与实时 HRV 反馈 | 将生理指标反馈组织为可理解的练习过程 | 未采用其 coherence 指标，不能把当前 stability 等同于该指标 |
| [nfreear/breath](https://github.com/nfreear/breath) | Web / SVG 呼吸动画 | 轻量前端、简单节律引导 | 开源交互参考；未逐文件审计许可证，不复制代码或资源 |
| [Three.js](https://github.com/mrdoob/three.js) | 通用 WebGL 渲染引擎 | React 中创建参数化 GPU 粒子场 | 实际使用的开源依赖；[MIT 许可](https://github.com/mrdoob/three.js/blob/dev/LICENSE)；保留依赖许可 |

设计选择：借鉴 Muse 的环境反馈逻辑、DEEP 的身体与场景联系、Moonbird 的引导与测量分离；用 React + Three.js 独立开发。没有查到并确认一个可以直接替换进渐静后端的完整开源产品，因此没有把商业产品当成可直接 fork 的代码。

## 视觉映射

| 已有字段 | 呈现方式 | 设计原因 |
|---|---|---|
| visual.intensity | 粒子场尺寸、可见强度 | 为淡出与结束保留控制；end 最终透明 |
| visual.noise | 球面半径形变、局部相位扰动 | 高扰动显得起伏不齐，低扰动趋于有序 |
| visual.speed | 累计动画时间的推进速度 | 不直接将时间乘以新速度，防止参数更新时位置跳变 |
| state.arousal | 铜橙到青蓝的辅助颜色、指数和描述 | 颜色辅助；运动承担主要状态反馈 |
| state.stability | 单独的稳定度条 | 稳定不等于低唤醒；assess 时显示建立参考中 |
| ritual.inhale_sec / exhale_sec | 独立呼吸环与文字引导 | 使用后端目标节奏，不拿实测 resp_rate 替代引导节奏 |
| ritual.stage / message | 阶段说明与提示 | 0/0 为自然呼吸，switch_method 不继续定时呼吸，end 不宣称入睡 |

所有动画参数以指数平滑 `alpha = 1 - exp(-dt / 2.8)` 逼近新值。2.8 秒是时间常数，约 8.4 秒到达目标差值的 95%，不是医学参数。页面标签阈值 0.38、0.65 是展示分段，不能作为心理状态科学分级。轻柔动效降低扰动和运动速度，默认尊重系统减少动态效果偏好。

当前高唤醒呈现较强、不规则的流动，但不使用屏幕闪烁或镜头震动。减少感官刺激是此原型的设计取舍，并未通过临床试验证明其效果。

## 原型与实测的区别

- 页面默认一分钟合成演示，轨迹从 0.82 到 0.18，最后 8 秒淡出。它不是后端 180 秒轨迹的精确回放，也不是实测疗效。
- 手动模式将一维唤醒值映射成示例参数，便于演示。真实连接时独立使用后端各字段，不强制让 arousal 和 stability 反相关。
- 心率与呼吸只是输入特征；现有仓库已明确 arousal/stability 是 prototype state index。没有依据将其直接判为愤怒、悲伤或焦虑诊断。
- 如果后续需要具体情绪，应先确定标注、自评、个体基线与验证方案；可视化组件不负责诊断。
- 若后续加入 LLM，建议用于有依据的提示文案；不应每帧调用模型生成动画参数。

## 后续开发优先级

1. 和队友在可信环境接通已有 WebSocket，验证实际设备、网络断开与会话重置。
2. 在目标手机/电脑上做交互与帧率测试，检查不同状态是否有可辨识的变化，以及是否觉得过度刺激。
3. 先完成小范围可用性评估，再讨论视觉反馈是否改善主观体验；不从动画变化推导疗效。
